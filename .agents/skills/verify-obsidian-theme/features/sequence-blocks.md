# Sequence blocks

The sequence plugin (`obsidian/sequence-plugin/`, flake attribute `obsidian-sequence-plugin`, plugin id `sequence-blocks`) renders `fasta`, `dna`, `rna`, and `protein` code blocks in the GenBank layout, and the theme's `obsidian/theme/src/sequence.css` draws them as manuscript cells. Whatever shape the input has, the block stays inside the note column and shows as many groups of ten per line as fit it, up to 60 residues, with the start position on each line, and copying gives back the sequence as written. These checks need a run launched with `--plugin obsidian-sequence-plugin`; without it the same notes show plain code blocks.

## Sub-features

- `seq-lines` sets the residues per line to the largest multiple of ten, from 10 to 60, whose line fits the block, the last line of a record shorter. Resizing the window lays the lines out again. Blocks under 1000 residues in one note get the same line length.
- `seq-groups` splits each line into groups of ten with a space between groups.
- `seq-pos` puts the start position (1, 41, 81, ... at 40 per line) before each line, right-aligned in tabular numerals, so the groups of every line start in one column.
- `seq-header` shows a FASTA `>` header line styled apart from the residues. The plugin writes the `>` as text in its own element (`.seq-header-mark`), so a copied selection keeps it, and the theme draws it once, in the muted colour at normal weight. The header text is ink, like the residues; blue stays on the printed parts, the top rule, the cell lines, and the badge. A long header wraps onto more lines and is never cut off. A block without a header (the `dna` block) has no header text.
- `seq-length` shows each record's length and unit in a badge. The fence names the molecule: a `dna` or `rna` block counts nt and a `protein` block aa, and each badge opens with a cell naming the molecule, `DNA`, `RNA`, or `Protein`, inside the badge's frame and parted from the length by one shared line (`[RNA|60 nt]`). A `fasta` block names no molecule and reads the unit from each record's letters: aa when it holds E, F, I, J, L, O, P, Q, Z, or `*` in either case (`96 aa`), nt when it holds only A, C, G, T, U, and N (`174 nt`), and nt/aa otherwise (`24 nt/aa`); X or an ambiguity code such as R keeps nt/aa. Alignment gaps, `-` and `.`, do not decide the unit, so `ACGT-ACGT` reads nt, but they count in the length. So a declared molecule and a unit read from the letters look different. The badge covers no residue and no header text. The badge holds the length and the unit in two parts: the unit part is as wide as the block's widest unit, 2ch in a block of `nt` or `aa` records and 5ch when a record says `nt/aa`, and the length part is as wide as the block's longest length, so every badge in a block, and every badge whose block has lengths of as many digits, as wide a unit, and as long a molecule name, has one width. The badge is one cell tall plus its border. It sits on the record's head row, and its right edge lines up with the right edge of the last cell of a full line at the block's line length, so the badges of all records, and of every block in the note, stand on one edge, a 24 nt primer's included, and the badge moves with that edge when the block reflows. The header wraps before it, and when the header leaves no room beside it, the badge moves to the next line. The lines take the block's full width, so reading view and Live Preview set as many residues per line at the same width. In Live Preview Obsidian's edit button sits at the block's top left, over the empty position column, so it covers no badge. Hovering the badge shows a tooltip that names the copy and spells out the unit. It starts `Copy · `, and a declared molecule comes first: `Copy · DNA, 96 nucleotides`, `RNA, 60 nucleotides`, `Protein, 214 amino acids`. A `fasta` record's tooltip says the unit was read from the letters and names the fence that would settle it: `174 nucleotides, read from the letters. Use a dna or rna block to say which.`, `96 amino acids, read from the letters. Use a protein block to say so.`, or `24 residues, nucleotides or amino acids. Use a dna, rna or protein block to say which.` A length of 1 takes the singular. A record without a header has a head row with only the badge.
- `seq-records` separates the records of a multi-FASTA block with a fine rule, and each record numbers its lines from 1.
- `seq-cells` draws each residue in a square cell, and cells sit only behind residues: the gaps between groups, the position column, and the empty end of a short last line have none.
- `seq-column` keeps the block inside the 700px note column: its left and right edges meet the column's, and it never scrolls sideways.
- `seq-reflow` gives the same layout to every input shape: one long line, lines wrapped at 60, 70, or 80, multi-FASTA records of 42, 60, and 132 nt, a 214 aa protein, a 60 nt RNA, and a GenBank `ORIGIN` paste, whose position numbers and `ORIGIN` and `//` lines the plugin drops.
- `seq-copy` returns the original text: a record's length badge copies its source exactly, and a selection copied from the block carries no position numbers or group spaces. The badge is the block's only copy control, the same in reading view and Live Preview; there is no copy icon, copy button, or language flair. A click, a tap, or Enter or Space on a focused badge copies. In a one-record block the badge copies the fence's text, the same text as `seq-command`. In a multi-FASTA block each badge copies its own record as the fence writes it, from its `>` header line to the line before the next header, without the blank lines after it. The lines of an indented fence, or of a fence in a list item, lose the indentation Markdown strips. The badge is a button (`role="button"`, `tabindex="0"`) with a pointer cursor; hovered, it sits on rule blue at 12%, and focused from the keyboard it takes the theme's focus ring. After a copy it fills with rule blue, with paper text and molecule divider, for one second, a notice names what it copied (`Copied 174 nt`), and a polite live region in the block says the same. A press in Live Preview keeps the editor's focus and cursor where they were and leaves the block rendered. On a phone the badge is a touch target at least 24px each way, without looking larger. When the clipboard refuses the text, an Obsidian notice says `Could not copy the sequence. Select the block and press ⌘C.`, with `Ctrl+C` on other desktops and `choose Copy` in place of the key on a phone or tablet, and the badge stays as it was.
- `seq-command`: the command `Copy sequence block at cursor` copies what a one-record block's badge copies, the fence's text, when the editor cursor is in a `fasta`, `dna`, `rna`, or `protein` fence, its fence lines included. A notice then names what it copied (`Copied 174 nt`, or `Copied 3 records`), and the failure notice of `seq-copy` shows when the clipboard refuses. With the cursor anywhere else, the command palette does not offer it. A fence inside a blockquote or callout does not count, nor does a fence indented four or more spaces inside a list item, such as a fence four spaces under `1. item`. The command reads fences indented at most three spaces and does not track list indentation. The badges of these blocks still copy.
- `seq-inline` leaves an inline primer in backticks as ordinary inline code, ungrouped and unnumbered.
- `seq-live` renders the blocks in Live Preview as in reading view. Hovering a block draws no box around it, and hovering Obsidian's edit button turns its icon blue without a tile, so the cut corner stays whole.
- `seq-dark` keeps every sub-feature above in the dark palette.
- `seq-phone` keeps the block inside the phone width without scrolling sideways; lines drop to 20 residues.

## How to get to it (user POV)

- Install the plugin in the vault and enable it under Settings, Community plugins.
- Write a code block fenced with `fasta`, `dna`, `rna`, or `protein` and open the note in reading view or Live Preview.
- Click or tap a record's length badge, or Tab to it and press Enter, in reading view or Live Preview. Or select residues and press `Cmd/Ctrl+C`.
- Hover a length badge to read what it copies and its unit spelled out.
- In Live Preview or source mode, put the cursor in a block's fence and run `Sequence Blocks: Copy sequence block at cursor` from the command palette.

## Driving it with obsidian.ts

Preconditions:

- Baseline preconditions hold for run `agent`, launched with `obs launch --run agent --plugin obsidian-sequence-plugin`.
- `obs doctor --run agent` lists `sequence-blocks` in `enabledPlugins` and reports `installCurrent: true`. After an edit under `obsidian/sequence-plugin/`, run `obs sync --run agent`.

- **Every input shape, light.** Run `obs shot --run agent --note sequences --view reading --scheme light` and again with `--scroll 600` and `--scroll 1200`. Together they show `seq-lines`, `seq-groups`, `seq-pos`, `seq-header`, `seq-records`, `seq-cells`, `seq-column`, `seq-reflow`, and `seq-inline` on the last capture.
- **Live Preview.** Run `obs shot --run agent --note sequences --view live --scheme light`. The capture shows `seq-live`.
- **Dark.** Repeat the three reading captures with `--scheme dark` for `seq-dark`.
- **Phone width.** Run `obs shot --run agent --note sequences --view reading --scheme light --mobile`, and again with `--scroll 700`, for `seq-phone`.
- **Lab notes.** Run `obs shot --run agent --note lab-note-ko --view reading --scheme light` for a sequence block among prose.
- **Layout and copy.** Run `obs seqcheck --run agent --view reading --scheme light`, again with `--size 1100x800`, again with `--view live --size 1100x800`, and again with `--view reading --mobile`. Each prints `SEQCHECK ok` or `SEQCHECK fail <count>` and writes `build/verify/agent/seqcheck-<view>-<scheme>-<size>[-mobile].json`. A `FAIL` line names the block, the invariant, and what was measured, without the rule. The invariants below are the rules, each with the sub-feature it proves. Every expectation is built from the fence's text and language in the note, never from the plugin's output. Lengths are CSS px.
  - `rendered`: the fence has a rendered block. A fence without one fails here and runs no other invariant.
  - `not-clipped` proves `seq-column` in reading view, `seq-live` with `--view live`, and `seq-phone` with `--mobile`. No ancestor up to the view's scroller whose overflow is not `visible` cuts the block's left or right edge, and the block's left edge is not left of the scroller's.
  - `fits` proves `seq-lines`: the chosen line length fits without scrolling, at every size and with `--mobile`. The block has no horizontal scroll (`scrollWidth <= clientWidth + 1`).
  - `in-column` proves `seq-column`, and `seq-phone` with `--mobile`. The block's left and right edges each lie within 1px of the note column's content edges: `.markdown-preview-sizer` in reading view, `.cm-content` in Live Preview.
  - `one-cut` proves the hover half of `seq-live`. No ancestor of the block up to the note column draws a border, an outline, or a box-shadow around the frame, and no control within the frame's top-right cut square, hovered on its own, paints a background over the 45° cut, as Obsidian's edit button does in Live Preview.
  - `badge-clear`, `badge-column`, `badge-edge`, `badge-height`, `badge-kind`, `badge-width`, and `badge-unit` prove `seq-length`, and `badge-label` its tooltip.
    - `badge-clear`: each record's badge (`.seq-badge` on its head row) overlaps no `.seq-group` and no header text. The header text box comes from a Range over the header's text, not the full-width header div.
    - `badge-column`: every badge in the block has the same width and the same right edge, within 0.5px.
    - `badge-edge`: every badge in the note has its right edge within 1px of the right edge of the last cell of a full line. A full line is a `.seq-line` that is not its record's last, so the plugin wrapped after it. Every full line in the note must hold as many residues as the others and end its last cell within 1px of theirs. A note in which no record runs past one line has no known full line and fails. A cell's edge is the last `.seq-group` of its line, less the right inset of its `clip-path`. The check compares x positions only, so blocks measured at different scroll positions compare.
    - `badge-height`: each badge is one cell (a `.seq-group`'s height) plus its 2px border tall, within 0.5px.
    - `badge-kind`: in a `dna`, `rna`, or `protein` block each badge holds a molecule cell (`.seq-badge-kind`) reading `DNA`, `RNA`, or `Protein`. The cell sits against the frame's inner left, top, and bottom edges within 0.5px, its right border has the frame's width, style, and colour, and the length starts at or after that line. A `fasta` block's badges hold no molecule cell.
    - `badge-width`: a block's badges are as wide as those of the first block whose longest record has the same number of digits, whose widest unit has as many letters (`nt` and `aa` two, `nt/aa` five), and whose molecule name has as many letters (none in `fasta`, three for DNA and RNA, seven for Protein), within 0.5px. A block with no such earlier block has no `badge-width` result.
    - `badge-unit`: each badge's unit part is as wide as the widest unit text in its block, within 0.5px.
    - `badge-label`: each badge's `aria-label`, which Obsidian's `setTooltip` shows as its tooltip, is the text `seq-length` gives for the record.
  - `badge-copy`, `badge-key`, `badge-repeat`, and `copy-failure` prove the control half of `seq-copy`, by click and by Enter, on success and when the clipboard refuses. Every press goes through a `writeText` recorder.
    - `badge-copy`: a mouse click at each badge's centre passes exactly one text to the recorder, the text `seq-copy` gives for that record.
    - `badge-key`: the first badge, focused with `focus()`, takes an Enter keypress and passes the text `badge-copy` expects to the recorder. In Live Preview the cursor first sits on the nearest line above the fence that is outside every fence, and the note's text must be unchanged after the keypress, so an Enter that reached the editor fails.
    - `badge-repeat`: with the first badge focused, Enter held down through three key repeats passes one text to the recorder, and in Live Preview leaves the note's text unchanged.
    - `copy-failure`: with `writeText` replaced by one that rejects, a click at the first badge's centre shows one Obsidian notice with the failure text `seq-copy` gives for the platform, and leaves the badge without `is-copied` and the live region empty.
  - `badge-held` and `badge-overlap` prove the copied state, the notice, and the announcement of `seq-copy` for their one second.
    - `badge-held`: a quarter second after each click, with the pointer still on the badge, the badge has `is-copied`, its background is `var(--wg-rule)` and its text `var(--wg-paper)`, a molecule cell's divider is `var(--wg-paper)`, the block's one `aria-live` region says `Copied <length> <unit>` for that record, and one notice says the same. The colours are resolved on a probe element in the block. 1.25 seconds after the click, with the pointer off the window, `is-copied` is gone and the region is empty.
    - `badge-overlap` (blocks of two or more records): the first badge is clicked, then the second about 0.6 seconds later. 0.75 seconds after the second click, past the first click's 1 second, the second badge still has `is-copied`, the region says `Copied <length> <unit>` for the second record, and the first badge has lost `is-copied`.
  - `badge-target` proves the 24px touch target of `seq-copy`. Hit-testing every half pixel within 24px of each badge finds the area where a click or tap reaches it. That area is at least 24px each way, within the half-pixel step, and its box covers no header text and no group. The badge is drawn smaller, and the plugin's styles give it an invisible `::before` that makes up the area.
  - `live-source` proves, with `--view live`, that a press leaves the editor as it was. Before each badge click the editor has focus and its cursor sits on the nearest line above the fence that is outside every fence. After the click the block is still rendered, the editor still has focus, the cursor is on the same line, and the note's text is unchanged.
  - `copy-selection` proves the selection half of `seq-copy`, and that the header keeps its `>`. With the whole block selected, a `copy` event carrying a fresh `DataTransfer` yields FASTA text. Each record gives its `>` header line, when it has one, then its residues without whitespace or digits, and records are joined by newlines. A line that starts with `ORIGIN` or is `//` adds nothing.
  - `copy-command` proves `seq-command` with `--view live`. With the editor cursor on the fence's first residue line, the command `sequence-blocks:copy-sequence-block` is available, running it passes exactly the fence's text to the recorder, and one notice starting `Copied` shows. With the cursor on the nearest line above the fence that is outside every fence, the command's `checkCallback(true)` returns false and running it writes nothing. `executeCommandById` returns true whether or not the command ran, so the check reads availability from `checkCallback`.
- **Tooltip and failure notice.** `seqcheck` checks their text but captures neither. Look at them in a probe run by `obs drive`: move the mouse onto a badge through CDP and wait a second for the tooltip, then replace `writeText` with a recorder that rejects and click the badge for the notice.
- **Cut corner.** Run `obs joins --run agent --scheme light`, again with `--view live`, and both with `--mobile`. The `cut` row measures each block's top rule into its 45° cut, in `lab-note-ko` and `sequences`.
- **Proof.** Look at every capture against the sub-feature list and report each sub-feature as holding or not, with the capture path.

## Gotchas

- A run launched without `--plugin` shows plain code blocks. `doctor` then lists no `sequence-blocks` in `enabledPlugins`.
- `sync` disables and re-enables the plugin, so an open note re-renders its blocks with the new code. Fixture notes still need a relaunch.
- `seqcheck` replaces `navigator.clipboard.writeText` for its clicks and never writes the system clipboard. A hand-written drive must do the same: clicking a badge for real puts the sequence on the owner's clipboard.
- `seqcheck` emulates `prefers-reduced-motion: reduce` while it runs, and forces hover on the block and its ancestors through CDP while it measures.
- `shot` captures show the badge at rest only. Its hover, focus, and copied states need a probe run by `obs drive` that forces `:hover` or `:focus-visible` with CDP, or clicks it with the recorder in place. In Live Preview the hovered captures `seqcheck` writes to `shots/seqcheck-*.png` show Obsidian's edit button at the block's top left, since `seqcheck` hovers the block's ancestors.
- `--scroll` values depend on the window height and on the note; check that each capture shows the intended block before reporting.
